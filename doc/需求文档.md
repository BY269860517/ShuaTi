\# Codex 工程任务书：PDF 原题导入刷题小程序 MVP



你是资深 uni-app + 微信小程序云开发工程师。请根据以下需求，完整实现一个微信小程序 MVP。



项目名称：PDF 原题导入刷题小程序



核心目标：

用户上传自己的 PDF 刷题资料。系统不接入 AI，而是通过规则解析 PDF 中已有的题目、选项、答案和解析，生成候选题。用户在小程序中预览、编辑、确认导入后，题目进入正式题库。用户可以刷题、提交答案、记录错题、复刷错题。



重要原则：

1\. 第一版不接入任何 AI。

2\. 不调用 OpenAI、DeepSeek、混元或任何大模型接口。

3\. AI 只做字段和策略接口预留，二期再实现。

4\. 第一版只支持文本型 PDF，不支持扫描图片型 PDF。

5\. 第一版只支持客观题：单选题、多选题、判断题。

6\. 解析结果不能直接全部入库，必须经过“解析预览 / 人工确认 / 编辑修正”流程。

7\. 用户数据必须严格按 openid 隔离，不能跨用户访问。

8\. AI Key、第三方服务 Key 等不要出现在第一版代码里。



技术栈：

1\. 前端：uni-app + Vue 3。

2\. 运行端：微信小程序。

3\. 后端：微信云开发 / CloudBase 云函数，Node.js。

4\. 数据库：CloudBase 云数据库。

5\. 文件：CloudBase 云存储。

6\. PDF 文本解析：Node 包 pdf-parse。

7\. 题目解析：自研规则解析器。

8\. 前端调用云函数：微信小程序环境优先使用 wx.cloud.callFunction。

9\. 文件上传：微信小程序环境优先使用 wx.cloud.uploadFile。



环境变量：

CLOUDBASE\_ENV=你的云开发环境 ID



如果当前项目还没有配置环境 ID，请使用占位符 your-env-id，并在 README 中说明用户需要替换。

\## 一、产品范围



\### 1. MVP 必须实现



1\. 用户登录初始化。

2\. 上传 PDF。

3\. 创建资料 material。

4\. 创建 PDF 解析任务 parse\_job。

5\. 解析 PDF 文本。

6\. 通过规则抽取题目、选项、答案、解析。

7\. 生成 parse\_candidates 候选题。

8\. 候选题预览。

9\. 候选题编辑。

10\. 确认导入正式题库 questions。

11\. 基于题库刷题。

12\. 提交答案并判题。

13\. 记录答题记录 attempts。

14\. 答错自动进入错题本 wrong\_questions。

15\. 错题复刷。

16\. 连续答对 3 次后标记为已掌握。

17\. 删除题库。



\### 2. MVP 不做



1\. 不做 AI 生成题目。

2\. 不做 AI 识别题目。

3\. 不做 OCR。

4\. 不做扫描版 PDF。

5\. 不做公共题库分享。

6\. 不做付费会员。

7\. 不做主观题自动评分。

8\. 不做班级、老师、学生系统。

\## 二、用户流程



完整流程：



1\. 用户进入首页。

2\. 如果没有题库，展示空状态。

3\. 用户点击“上传 PDF”。

4\. 用户选择 PDF 文件。

5\. 前端校验：

&#x20;  - 文件后缀必须是 .pdf。

&#x20;  - 文件大小不超过 20MB。

6\. 前端上传 PDF 到云存储。

7\. 前端调用 materialCreate 创建资料记录。

8\. 前端调用 parseStart 创建解析任务。

9\. 前端进入资料详情页。

10\. 资料详情页显示“解析中”。

11\. 前端调用 parseRunner 或等待定时任务执行 parseRunner。

12\. 前端轮询 parseStatus。

13\. 解析完成后，material.status = reviewing。

14\. 用户点击“查看解析结果”。

15\. 用户进入解析预览页。

16\. 用户查看候选题。

17\. 用户可以编辑、忽略、勾选候选题。

18\. 用户点击“确认导入”。

19\. 系统把 ready 状态的候选题写入 questions。

20\. material.status = ready。

21\. 用户开始刷题。

22\. 用户提交答案。

23\. 系统判断对错。

24\. 答错则写入 wrong\_questions。

25\. 用户可以进入错题本复刷错题。

\### 2. 上传页：src/pages/upload/upload.vue



功能：

6\. 选择解析模式 parseMode：

10\. 调用 parseStart。

上传路径建议：

materials/{openid}/{timestamp}\_{fileName}



注意：

前端不要信任 openid，openid 只在云函数里获取。上传路径里如果需要 openid，可以先调用 userLogin 拿到 openid 仅用于路径拼接，但后端仍然必须校验 ownerOpenid。

\### 2. 文本标准化规则



实现 normalizeText(text)：



1\. \\r 替换为 \\n。

2\. 中文冒号统一为英文冒号或内部统一格式。

3\. 中文括号统一。

4\. 全角点号统一。

5\. 连续空格压缩。

6\. 连续 3 个以上换行压缩为 2 个。

7\. 保留必要换行，因为题目切分依赖换行。



参考实现：



function normalizeText(text) {

&#x20; return String(text || '')

&#x20;   .replace(/\\r/g, '\\n')

&#x20;   .replace(/\[ \\t]+/g, ' ')

&#x20;   .replace(/．/g, '.')

&#x20;   .replace(/：/g, ':')

&#x20;   .replace(/（/g, '(')

&#x20;   .replace(/）/g, ')')

&#x20;   .replace(/【\\s\*/g, '【')

&#x20;   .replace(/\\s\*】/g, '】')

&#x20;   .replace(/\\n{3,}/g, '\\n\\n')

&#x20;   .trim()

}

\### 7. 判断题处理



如果题目是判断题，统一转换为：



{

&#x20; type: "true\_false",

&#x20; options: \[

&#x20;   { key: "A", text: "正确" },

&#x20;   { key: "B", text: "错误" }

&#x20; ],

&#x20; answerKeys: \["A"]

}



如果答案是“错 / 错误 / ×”，answerKeys = \["B"]。



判断题识别依据：

1\. 标题包含 判断题。

2\. 题干包含“正确 / 错误 / 对 / 错 / √ / ×”答案。

3\. 没有 A/B/C/D 选项，但答案是正确/错误类。



\---



\### 8. 多选题识别



多选题识别依据：

1\. 标题包含 多选题 / 多项选择题。

2\. answerKeys 长度 >= 2。



如果 type 未识别：

1\. answerKeys 长度 = 1 => single\_choice。

2\. answerKeys 长度 >= 2 => multi\_choice。

3\. 答案是正确/错误 => true\_false。

4\. 仍无法识别 => unknown。



unknown 不允许导入，status 应为 need\_review 或 invalid。



\---



\### 9. 集中答案区解析



支持：



参考答案：

1.B 2.A 3.C 4.AB 5.D



也支持：



1、B

2、A

3、A C

4、错



建议正则：



const ANSWER\_MAP\_RE =

&#x20; /(\\d{1,4})\\s\*\[\\.\\、\\)]\\s\*(\[A-H](?:\\s\*\[、,，\\s]?\\s\*\[A-H])\*|正确|错误|对|错|√|×)/g



输出：



{

&#x20; "1": \["B"],

&#x20; "2": \["A"],

&#x20; "3": \["A", "C"],

&#x20; "4": \["B"]

}



当 parseMode = answer\_at\_end：

1\. 先检测答案区。

2\. 拆分题目区和答案区。

3\. 从答案区解析 answerMap。

4\. 题目区切题。

5\. 用 originalQuestionNo 去 answerMap 找答案。

\### 10. 解析置信度评分



每个 candidate 都要有 parser.confidence。



加分：

1\. 识别到题号：+10。

2\. 题干长度 > 8：+10。

3\. 识别到 2 个以上选项：+20。

4\. 识别到答案：+25。

5\. 答案存在于选项中：+15。

6\. 识别到解析：+10。

7\. 类型明确：+10。



扣分：

1\. 题干过短：-20。

2\. 没有答案：-30。

3\. 答案不在选项中：-40。

4\. 选项数量少于 2：-40。

5\. 疑似切题失败：-30。



状态规则：

1\. valid \&\& confidence >= 80 => ready。

2\. confidence >= 50 => need\_review。

3\. 否则 invalid。



特殊规则：

parseMode = question\_only 时，没有答案不应直接 invalid，而是 need\_review，用户后续手动补答案。



\---



\### 11. 候选题校验规则



validateCandidate(candidate) 必须检查：



1\. stem 不为空。

2\. type 必须是 single\_choice / multi\_choice / true\_false。

3\. options 至少 2 个。

4\. option key 不能重复。

5\. answerKeys 不能为空，除非 parseMode = question\_only。

6\. answerKeys 必须都存在于 options。

7\. single\_choice 只能有 1 个答案。

8\. multi\_choice 至少 2 个答案。

9\. true\_false 必须有 A/B 两个选项。

10\. duplicateHash 必须生成。

11\. stem 过短要 warning。

12\. explanation 为空要 warning，但不一定 invalid。
